## Цель

Критерий успеха кейса: «На главном экране интернет-приложения Альфа-Бизнеса есть заметная
и постоянно доступная точка входа в сервис». Нужен контракт, по которому приложение банка
показывает вход в «Пульс бизнеса» и открывает сервис без повторной авторизации.

## Область изменений

1. Вход по подписанной ссылке (launch): `POST /api/v1/auth/launch`.
2. Виджет для встраивания на главный экран банка: маршрут `#/embed` (iframe).
3. Демо-хост: страница `/host-demo.html`, имитирующая главный экран интернет-банка,
   и демо-подписант `POST /api/v1/host-demo/launch-link` (включается `HOST_DEMO=true`).
4. Заголовок `Content-Security-Policy: frame-ancestors` для HTML.
5. Документация `docs/integration.md`, тесты.

Вне области: настоящий SSO банка, мобильное приложение, push-уведомления.

## Требования

- Launch-токен подписывает банк общим секретом `HOST_LAUNCH_SECRET` (HMAC-SHA256),
  формат `base64url(json).base64url(hmac)`. Поля: `sub` (логин), `company`, `exp`, `nonce`,
  необязательный `target`.
- Срок жизни не более 300 секунд; `nonce` одноразовый (таблица `launch_nonce`).
- `company` в токене совпадает с компанией пользователя.
- `target` проходит белый список: `home`, `feed`, `analyze`, `profile`,
  `insight/<id>`, `event/<id>`; иначе — `home`.
- Токен передаётся во фрагменте URL (`#/launch?t=…`), поэтому не попадает в логи серверов;
  после обмена фрагмент заменяется без записи в историю.
- Виджет работает в стороннем iframe без localStorage (токен держится в памяти),
  сообщает хосту высоту (`pulse:resize`), число новых событий (`pulse:badge`)
  и запрос на переход (`pulse:open`). Сообщения не содержат токенов и данных компании.
- Каждый вход по launch пишется в audit_log.

## Критерии приёмки

- Корректный токен даёт сессию и `target`; истёкший, с неверной подписью, повторный,
  с чужой компанией или неизвестным пользователем — 401 с понятным кодом.
- Демо-подписант недоступен (404), когда `HOST_DEMO=false`.
- `/host-demo.html` показывает главный экран с постоянной кнопкой «Пульс бизнеса» со счётчиком
  и виджетом; клик по событию открывает карточку инсайта в сервисе без экрана входа.
- HTML отдаётся с `frame-ancestors` из `EMBED_ALLOWED_ORIGINS`.
- Тесты, ruff, `tsc`, сборка UI проходят.

## Проверки

pytest, ruff, `npm run build`, сценарий в headless Chromium: host-demo → виджет → карточка.

## Риски

- Секрет хоста в демо по умолчанию слабый: в продакшне задаётся переменной окружения.
- Одноразовость nonce проверяется по БД; для нескольких инстансов нужна общая БД (Postgres).
