## Цель

По решению команды все генеративные шаги выполняют разрешённые модели: без ключа сервис не создаёт инсайты,
а не подменяет их шаблонами. Добавить OCR для отчётов и документов. Перейти на данные кейса из `data/`.

## Требования

- LLM-клиент: без `LLM_BASE_URL`/`LLM_API_KEY` — режим `off`, API отвечает 503 `llm_unavailable`; при исчерпании
  лимита — 503 `llm_budget`; ответ модели проверяется по схеме, при ошибке — повтор с замечанием, затем резервная
  модель, затем ошибка `llm_failed`.
- Модели выполняют: классификацию и извлечение фактов с дословными цитатами, план, анализ, проверку, чат, сводку,
  описание компании, описание графиков (Qwen3-VL).
- Детерминированными остаются: ранжирование, BM25, предфильтр новостей по ключевым словам, программные проверки.
- OCR: страницы PDF без текстового слоя и изображения — Tesseract `rus+eng`; загрузка файла в «Проверить новость».
- Очистка текста отчётов от чисел с графиков и дисклеймеров.
- Данные: при наличии CSV в `data/` сервис берёт их; без `users.yaml` создаются демо-учётки для крупнейших клиентов.
- Тесты используют тестовый двойник транспорта модели (`tests/llm_stub.py`), в продукте он не подключается.

## Критерии приёмки

- Без ключа: баннер «Модели не подключены», 503 на чат и анализ, профиль открывается.
- С шлюзом: фоновая обработка классифицирует новости, готовит инсайты, сводки и описания; трасса показывает модели.
- OCR распознаёт скан PDF; тесты, ruff, сборка UI проходят.

## Риски

- Демонстрация зависит от шлюза организаторов; ID моделей в `config/models.yaml` нужно сверить.
- Стоимость: полный прогрев демо — порядка десятков рублей при предполагаемых тарифах.
