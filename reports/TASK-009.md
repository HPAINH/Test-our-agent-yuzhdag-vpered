# TASK-009 — Сервис на моделях, OCR, данные кейса

**Результат.** Генерацию выполняют только разрешённые модели: классификация с фактами и дословными цитатами,
план, анализ, проверка, чат, сводка дня, описание компании, описание графиков (Qwen3-VL). Без ключа сервис
открывается, показывает профили и баннер «Модели не подключены», API анализа и чата отвечает 503. Ответ модели
принимается только после проверки схемы; при ошибке — повтор с замечанием, затем резервная модель.
Подключены данные кейса из `data/`: 85 513 компаний после очистки, 1,35 млн платежей без переводов себе,
9 отчётов Альфы, распознанных OCR (все PDF — сканы). Демо-учётки — на компаниях-клиентах из выборки.

**Проверки (самопроверка, не независимое ревью).**

- `pytest` — 54 теста (на тестовом двойнике транспорта модели), `ruff` — без замечаний, `tsc` и сборка UI — без ошибок;
- живой HTTP-путь: приложение в режиме `live` против локального OpenAI-совместимого имитатора шлюза — на данных
  кейса за 1,5 минуты: загрузка 85 тыс. компаний (42 с), 30 событий, 50 инсайтов, 6 описаний компаний,
  вызовы всех 5 маршрутов моделей; оценка расхода по предполагаемым тарифам — 32 ₽;
- без ключа: баннер, 503 на анализ, профиль открывается;
- OCR: 9 отчётов, 136 фрагментов, порядок колонок сохраняется; результат в `data/alfa/.ocr_cache`;
- браузер: вход `cfo_a`, лента, карточка с цитатой «Бонд Брифа», чат, профиль U_9250, переключатель компаний.

**Не проверено.** Настоящий шлюз организаторов (из среды разработки недоступен) и качество ответов настоящих
моделей; ID моделей в `config/models.yaml` — предположение; живые RSS-ленты; сборка Docker-образа.

**Ограничения.** `make eval` считает метрики по синтетической разметке; разметка на данных кейса — TASK-004.
База SQLite на данных кейса — около 450 МБ; для сервера рекомендуется PostgreSQL.

**Ветка.** `task/TASK-009-llm-ocr`, исходный коммит `f5d8285`.

**Готовность к слиянию.** После сверки ID моделей и проверки на шлюзе организаторов.
