# Встраивание в интернет-банк Альфа-Бизнес

Точка входа в «Пульс бизнеса» размещается на главном экране интернет-банка и доступна на всех экранах.
Банк не передаёт сервису пароли: он выпускает короткоживущую подписанную ссылку входа (launch-токен).

## Точки входа

| Где | Что показывает | Как открывает сервис |
| --- | --- | --- |
| Шапка интернет-банка, все экраны | Кнопка «Пульс бизнеса» со счётчиком новых событий | Ссылка входа с `target=feed` |
| Главный экран | Виджет: число событий, рисков, топ-3 события | iframe `/#/embed?t=…`; клик → ссылка входа с `target=insight/<id>` |
| Меню разделов | Пункт «Пульс бизнеса» со счётчиком | Ссылка входа с `target=feed` |

Демо: `/host-demo.html` изображает главный экран банка и проходит весь сценарий.

## Последовательность

```
Пользователь     Интернет-банк (бэкенд)          Пульс бизнеса
     | открыл главную  |                                |
     |---------------->| подписывает launch-токен       |
     |<----------------| iframe /#/embed?t=<токен>      |
     |------------------------------------------------->| POST /api/v1/auth/launch → сессия
     |                 |<-- postMessage pulse:badge ----| (счётчик для кнопки в шапке)
     | клик по событию |<-- postMessage pulse:open -----|
     |                 | новый токен с target           |
     |------------------------------------------------->| /#/launch?t=<токен> → карточка инсайта
```

## Launch-токен

Формат: `base64url(json) + "." + base64url(HMAC-SHA256(secret, base64url(json)))`, без `=`.

| Поле | Обязательно | Описание |
| --- | --- | --- |
| `sub` | да | Логин пользователя интернет-банка |
| `company` | да | Идентификатор компании клиента; должен совпадать с компанией пользователя |
| `exp` | да | Unix-время окончания; не позже чем через 300 секунд |
| `nonce` | да | Случайная строка 8–64 символа; повторно не принимается |
| `target` | нет | `home`, `feed`, `analyze`, `profile`, `insight/<id>`, `event/<id>`; иное → `home` |

Пример подписи на стороне банка (Python):

```python
import base64, hashlib, hmac, json, secrets, time

def b64(b: bytes) -> str:
    return base64.urlsafe_b64encode(b).decode().rstrip("=")

claims = {"sub": "cfo_a", "company": "U_DEMO_A", "exp": int(time.time()) + 120,
          "nonce": secrets.token_urlsafe(16), "target": "feed"}
payload = b64(json.dumps(claims).encode())
token = payload + "." + b64(hmac.new(SECRET, payload.encode(), hashlib.sha256).digest())
url = f"https://pulse.example/#/launch?t={token}"
```

Токен передаётся во фрагменте URL (после `#`), поэтому не попадает в логи веб-серверов и прокси.
После обмена фрагмент заменяется без записи в историю браузера.

## API

`POST /api/v1/auth/launch` — `{"launch_token": "…"}` → `{"token", "user", "target"}`.

Ошибки (401): `launch_malformed`, `launch_bad_signature`, `launch_expired`, `launch_ttl_too_long`,
`launch_unknown_user`, `launch_company_mismatch`, `launch_replayed`. Каждая попытка пишется в `audit_log`.

`POST /api/v1/host-demo/launch-link` — `{"login", "target"?}` → `{"launch_token", "url", "embed_url"}`.
Только для демо, выключается `HOST_DEMO=false`. В продакшне ссылки подписывает бэкенд банка.

## Сообщения виджета (postMessage)

Все сообщения имеют `source: "pulse"` и не содержат токенов или данных компании.

| type | Поля | Что делает хост |
| --- | --- | --- |
| `pulse:resize` | `height` | Меняет высоту iframe |
| `pulse:badge` | `count`, `risks` | Обновляет счётчик на кнопке в шапке и в меню |
| `pulse:open` | `target` | Выпускает новый launch-токен с этим `target` и открывает сервис |

Хост проверяет `event.origin` и `event.source` перед обработкой.

## Настройки

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `HOST_LAUNCH_SECRET` | `dev-host-secret-change-me` | Общий с банком секрет подписи; в продакшне — из хранилища секретов |
| `HOST_DEMO` | `true` | Демо-подписант и `/host-demo.html` |
| `EMBED_ALLOWED_ORIGINS` | `'self'` | Значение `frame-ancestors`: какие сайты могут встраивать виджет, например `'self' https://business.example` |

## Ограничения прототипа

- Пользователи заведены заранее; при подключении к банку их нужно создавать по первому входу.
- Одноразовость `nonce` хранится в БД сервиса; при нескольких инстансах нужна общая БД (PostgreSQL).
- Виджет в стороннем iframe держит сессию в памяти, без localStorage: при перезагрузке страницы банк выдаёт новый токен.
