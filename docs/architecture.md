# Архитектура

## Компоненты

| Компонент | Код | Что делает |
| --- | --- | --- |
| Загрузка профилей | `app/profile/loader.py`, `builder.py`, `store.py` | CSV → нормализованный профиль, позиция в отрасли, группа, контрагенты из платежей, неявные связи через физлиц, вектор факторов с основаниями |
| Сбор материалов | `app/ingest/news.py`, `alfa.py` | RSS, снимок новостей (JSONL), ручной ввод и URL с защитой от SSRF; отчёты Альфы (PDF/MD) → чанки со страницами |
| Обработка | `app/processing/` | очистка, удаление инъекций, классификация (LLM с фолбэком на правила), извлечение фактов с цитатами, кластеризация в события, привязка аналитики банка (BM25) |
| Ранжирование | `app/ranking/score.py` | S = 0.40F + 0.20I + 0.10R + 0.10B + 0.10T + 0.10E с множителями роли и разложением |
| LLM-клиент | `app/llm/client.py` | роутинг по 6 моделям, кэш, учёт ₽, ретраи и резервная модель, детерминированный фолбэк, mock-режим |
| Агент | `app/agent/` | Planner → инструменты → Analyst → Verifier → Adapt, лимиты запуска, трасса |
| Диалог | `app/agent/chat.py` | быстрые разрезы по инсайту, RAG по новостям и аналитике, отказ вне темы |
| API | `app/api/` | REST + SSE, сессии, rate limit, аудит |
| Мониторинг | `app/eval.py`, `app/monitoring.py` | офлайн-метрики на разметке, онлайн-метрики качества и расходов |
| UI | `ui/` | кабинет «в стиле» Альфа-Бизнеса: главная с виджетом, лента, карточка, трасса, чат, проверка новости, профиль, качество |
| Фон | `app/worker.py` | каждые 30 минут: сбор → обработка → ранжирование → прогрев инсайтов |

## Поток данных

1. `seed`/`worker` загружают профили и материалы, классифицируют новости и объединяют дубли в события.
2. Для каждой пары «компания × роль» считается значимость событий (`relevance`).
3. Для топ-5 событий (не более 2 одного типа) агент заранее готовит инсайты; остальные готовятся при открытии.
4. Пользовательская новость (`/analyze`) проходит тот же путь как приватное событие пользователя.

## Агент

| Шаг | Модель (live) | Фолбэк | Требование кейса |
| --- | --- | --- | --- |
| Planner | Qwen3.6 35B A3B | правила (`rule_plan`) | Планирование |
| Инструменты (9, только чтение) | — | — | Работа с инструментами |
| Analyst | GLM-5.3-Flash, резерв DeepSeek | шаблоны `config/interpretation.yaml` | Интерпретация, К-02 |
| Verifier | 7 программных проверок + Kimi-K2.6 | только программные | Самопроверка |
| Adapt | — | — | повторный поиск, связанные события, удаление неподтверждённых утверждений; ≤ 2 итераций |

Общий контекст — `RunContext`: профиль, событие, найденные материалы и отчёты, связанные события, продукты, план.
Лимиты: 12 вызовов инструментов, 8 вызовов LLM, 30 000 токенов.

## Контракт инсайта

`app/schemas.py::InsightBody`. Каждое утверждение — `Claim` с `kind` = `fact | bank | ai` и непустым `sources`;
схема запрещает `fact` без материала и `bank` без отчёта банка.

## Хранилище

Таблицы: `company`, `company_factor`, `company_link`, `app_user`, `material`, `event`, `relevance`, `insight`,
`trace`, `llm_call`, `llm_cache`, `feedback`, `ui_event`, `audit_log` (`app/db/models.py`).
